# API_CALL_TIMEOUT_SECONDS = 300 — Registered Constant, and the Undifferentiated-Failure Principle

- **Artifact:** `docs/registrations/api_call_timeout.md` — governing text. Committed per the standing convention; relay citations retire upon landing.
- **Ruled:** 2026-09-17 (registration, on Operations' inputs); the companion principle (§3) registered the same exchange. **Dates translated:** the grid-occupancy check runs in the **November 2026** validation month per `docs/amendments/phase_b_boundary_amendment_2026-12-01.md`.

## 1. The registered constant

> **Client-side API call timeout (registered constant).** `API_CALL_TIMEOUT_SECONDS = 300`, cohort-wide, enforced in `src/adapters/base.py` inside each adapter's `_call_api`, covering both the screening and decision legs. **Derivation, registered:** 300s clears the highest observed successful-call latency in the stable Aug–Sep baseline (214.1s across all six models) with ~40% headroom; halves the undocumented 600s provider transport default that previously bounded these calls; and equals `DEFAULT_FILL_DEADLINE_SECONDS = 300`, giving the system **one** registered "too long to wait" constant across the LLM-call and broker-fill boundaries rather than two that could drift independently. **Semantics:** a timed-out call routes through the fail-fast branch and returns immediately — one 300s stall per call, never compounded across attempts; only parse failures retry. A timed-out call is a failed decision leg, counted in completeness denominators, excluded from latency statistics per the outcome-class conditioning rule. **Grid bound:** worst case per model per tick is 300s × 2 legs = 600s — 50% of the 20-minute spacing budget from a single arm — registered as the binding input to November's per-arm grid-occupancy check.
>
> **Derivation caveat (owned tradeoff):** the 214.1s baseline maximum is drawn from a window in which the Gemini provider-availability event class (registered, recurrable without warning) was dormant. Under recurred provider degradation, the timeout trades possibly-completable slow calls for bounded grid cost and clean failure accounting — **by design**: a bounded failure beats an unbounded stall, and the completeness gate and occupancy check surface any recurrence immediately, in the right category. **First exceedance (recorded 2026-11-17):** on 2026-11-05T18:38:53Z an xAI decision call was clipped at the constant (300.1s; `Read timed out. (read timeout=300)`) — the first call to reach it, against the 214.1s baseline maximum, and from an arm outside the event class this caveat names. Whether it would have completed cannot be known from a clipped call. One event does not move the constant; it is the first datum on the tradeoff owned here.

## 3. The undifferentiated-failure limitation (registered apparatus principle)

> An instrument that fails *inside an existing error category* is undetectable by the apparatus watching that category. Documented instances, one month: (i) client-side timeouts surfacing as generic adapter errors (the §2 record); (ii) a behavioral tripwire reporting success while measuring nothing; (iii) a scheduled-task registration echoing success while no task existed. The common shape: the failure mode's signature is absorbed by a category the monitoring already tolerates, so no counter moves and no alarm exists to fire. **Registered consequence:** instruments and infrastructure emit **distinguishable event classes for their own failure modes** — a timeout is a `TIMEOUT` event, not a generic error; a failure caused by the lab's own account standing at a provider is an `ACCOUNT_STATE` event, not provider unavailability (`docs/registrations/rossi_review_rulings.md` §2.4); a tripwire that cannot compute emits `MEASUREMENT_FAILED`, not silence; a registration that cannot verify emits a verification failure, not an echo. Monitoring that watches categories can only see what the categories separate. **Implemented:** the timeout differentiation landed at `57c8fd8` (2026-11-15, "Log TIMEOUT, Gemini model_version_raw, Grok search provenance, BARRIER_DELAYED"), which introduced `ERROR_CLASS_TIMEOUT` and `is_client_timeout` in `src/adapters/base.py` and the decision record's `api_error_class` field. `ACCOUNT_STATE` is registered here ahead of its code: it lands as a logging-only package before 2026-12-01 (hub decision 2026-11-16), and until then the class is assigned from stored `api_error` text. Later instances of the principle are recorded where they were found: the executor sizing floor (`docs/registrations/executor_sizing_floor_ruling.md` §⑤) and account-state failures filed under provider availability (`rossi_review_rulings.md` §2.4).

Cross-reference (one-directional, this artifact → the integrity framework): this principle is the monitoring-layer sibling of the estimability taxonomy — the taxonomy classifies data known to be damaged; this principle governs how damage becomes knowable at all.
