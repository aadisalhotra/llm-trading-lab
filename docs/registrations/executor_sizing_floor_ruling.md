## ① The floor is removed — code corrects to registration

The registered sizing floor is **$1** (`docs/registrations/below_venue_minimum.md`): unexpressed residual < $1 per order, ≤0.05% of NAV, "the venue minimum functions as the $1 sizing-granularity floor, registered as such." The one-share floor loses whole orders — up to $400, 20% of NAV — contradicting the registered bound by three orders of magnitude. Registering the floor instead is rejected on two grounds: it is the forbidden arrow (registered text amended to match defective code), and it would reinstate the whole-share quantization the venue decision was made to escape — IBKR was disqualified on zero-tolerance T1 holdability and the 1.0pp T2 fidelity criterion, and at $2,000 books this floor reproduces the same T1 failure (COST, LLY, TMO unreachable under the $400 cap) on the venue chosen for fractional sizing. The floor is not a venue constraint (the venue accepts notional orders to $1); it is a $100k-era relic that scale converted from a frequent-but-cheap distortion into an unregistered design feature. The mislabel ("Insufficient cash" with cash present on 128 of 140) is a false reason in the record and is removed with it. Both sites are removed; the fix's report enumerates every remaining pre-submission skip path per §⑤. The frozen prompt is untouched: the fix is execution-layer, inside the validation month built for exactly this correction (precedent: the v4 component-2 rendering amendment).

## ③ G-EXEC: recomputed honestly under the existing taxonomy — no new class (corrected)

The registered gate already decides the classification: a cycle succeeds when its **intended orders** reach a terminal, broker-reconciled state. All 140 intended orders were deleted pre-submission by our own code — an execution-layer failure (ours), counted as failure; the venue linkage never engaging is the failure, not an exemption from it. **All 140 are untagged skips, and under the Gate 4 clause below an untagged skip is by definition an execution failure. Friday's per-book G-EXEC recomputes from the decision logs on 140 failures.**

**Correction to the first issue of this ruling (2026-11-06):** the first issue classified 12 of the 140 as "legitimate constraint events — execution-successful," on the ground that cash was below one share's price. That was wrong twice over. Cash below one share's price is not insufficient cash under fractional sizing — a book with $9.60 buys $9.60 of a $150 name, and the registered settled-funds behaviour caps an order at available cash rather than blocking it — so no constraint event occurred. And classifying them as successes applied what a correct executor *would have done* to what the executor *did* — the exact move this section rejects. The 12 are **execution failures as recorded**, carrying a **counterfactual annotation as disclosure only**: *a correct executor would have produced a cash-capped order and a tagged constraint event.* Disclosure, not reclassification.

Books failing 0.80 classify **decision-estimable (execution-impaired)** for the session — the registered taxonomy demonstrating itself on validation data at zero confirmatory cost — with the registered correlation disclosure applied: one defect event, correlated across five books by construction. A "disclosed defect segment" class is rejected: inventing a category to spare our own gate on a validation day would game the gate for cosmetics; a gate that fails when fed the truth is the gate working.

**Gate 4 text amendment (lands with this ruling):** *pre-submission suppression of an intended order is either a registered, tagged constraint event (venue minimum; settled-funds cap; barrier classes — execution-successful, censored per the censoring principle) or an execution failure. There is no third state; an untagged skip is by definition the second.*

## ⑤ The undifferentiated-failure extension — confirmed, made structural

Fourth documented instance of the registered principle (`api_call_timeout.md` §3), and the cleanest: the failure deleted its own evidence, so the gate watching the category saw nothing. Registered consequences:

1. **Every pre-submission skip path emits a classified event** carrying a constraint tag and the decision/order ID.
2. **The set of legal skip classes is closed and registered** (`BELOW_VENUE_MINIMUM`; the settled-funds cap; the barrier classes). A new skip class must be registered before it can exist in code. **The enumeration of existing skip paths is a sweep of the code, not a reading of reports:** both day-one reports described one floor and the code held two (`:449`, `:882`); the fix's report lists every pre-submission skip path found by search, with its site and its registered class or its removal.
3. **A skip without a registered class is itself an execution failure and an alarm** — the next dormant relic fails loudly on first firing, not silently for a month.
4. **The intended-vs-expressed deployment gap becomes a standing disclosed descriptor**, per book per session — the generic detector for silent suppression of any kind; it is what actually caught this defect, and it costs one subtraction.
