## 1. The hazard is wider than (b) as dispatched

Item 4 was a sound invariant in Phase A because every piece of state lived in the commit: a run that did not commit had, for every purpose, not happened. **In Phase B the venue is durable state outside the commit.** Fills survive whatever happens to the runner. So the dangerous state is not "a run killed partway through"; it is **any order at the venue that the committed record of its book does not account for**. Four routes reach it:

- the runner dies mid-loop (the dispatched case);
- the pipeline raises after the first order, so the commit step never runs;
- the run completes and the push fails five times — all five books filled, nothing committed;
- **one book raises inside a run that then commits normally.** `run_one_model` can submit orders at three sites — the pre-prompt stop sweep (`src/pipeline.py:265`, through `executor.force_liquidate` at `:214`), the model's decisions (`:477`) and the portfolio-stop liquidation (`:502`) — then saves the book once (`:532`) and writes the decision row (`:535`). The executor never saves. An exception after the first order is caught per book at `:901–905` (status `ERROR`), the other books finish, the slot is marked and the run commits. Neither guard sees it, and nothing that keys on run failure sees it either. The route has two halves, split at the save:
  - **Before `:532`** — the disk holds the pre-tick book. The window opens at the stop sweep, so when a stop fires it spans the whole model call. The same run's post-cycle reconciliation always runs (it takes every enabled venue book regardless of status, `:951–953`, and reloads each from disk, `reconciliation.py:458`), finds a position difference for any fill of at least the $1 venue minimum (a difference of exactly the bound counts, `:273`), and **halts every venue book, with persisted flags, in the run where it happened**. (V) plays no part: detection precedes the next tick.
  - **After `:532`** — the saved book matches the venue, reconciliation is clean, and the book has orders with no decision row. **Nothing sees this half except (V)'s id test.**

  On the failed-call path the order is reversed — the row is written at `:422` and the book saved at `:444` — so an exception between them leaves a row and a stale book: the id is accounted and only the quantity test catches it. The two tests are not redundant; each has a case the other cannot see.

And the exposure is not confined to a same-slot retry. In the first three routes the committed books are behind the venue, the decision rows for the filled books are gone, and no marker exists. **The next scheduled tick — a different slot, which neither guard covers — checks out the stale books and trades on them**: cash already spent is offered again, positions already bought are invisible. Post-cycle reconciliation then finds the divergence and halts every venue book (item 5), after one tick of stale-state orders with real money. In Phase B that is all five confirmatory arms censored by one book's lost commit.

Three consequences:

- **Per-book marking, as described, does not close (b).** A mark written to `data/state/handled_boundaries.json` as each book fills lives in the same working tree and reaches origin in the same end-of-run commit. It is lost in exactly the cases it exists for. A push per book narrows the window and cannot close it: the kill can fall between the fill and the push.
- **Money at risk is bounded by the stale book's beliefs, not by the venue (corrected rev. 3).** The first two issues said a duplicate SELL of shares already sold "is refused by a cash account". Operations tested it and that is true only for a name no other book holds. The books share one account, so where another book holds the symbol the stale book's SELL is filled from that book's shares; on the committed books at `3d1c04a`, 16 of the 32 symbols held are held by two or more books. A duplicate BUY is bounded by our own settled-cash cap (`settlement.enforce_settled_funds`) applied to the cash the stale book believes it has; the venue does not bound it, because the account holds more than any one book. The dollar exposure is therefore still roughly one tick's orders per book. The conclusion stands; the reason given for it was wrong on the SELL side and is withdrawn.
- **The damage that does not bound is to the record, in four modes:** executions with no decision row; books that no longer equal the venue; **cross-book misattribution** — a stale book's SELL satisfied from another book's shares, detected only afterwards and only as an account-level difference on the symbol (the same shared-account fact implies a stale book's BUY draws on cash that belongs to the other books; that side is an inference, not tested); and a cohort-wide halt in the confirmatory window.

## 2. Class — these are admission controls, not executor code

**Registered boundary (ghost-position ruling §①, restated):** executor-class is a change that alters the venue order a decision-and-state would produce. The S1 count validates that mapping.

**Admission class (registered here).** Code that decides whether a tick occurs, or whether a book takes part in it, **evaluated before that book's first possible order in the tick — which is the pre-prompt stop sweep, not the prompt**. Defining properties:

1. It acts before any decision exists. Both guards sit ahead of the fetch and the model loop (`pipeline.py:689`: "Checked BEFORE the data fetch and the model loop"), so a withheld run exits having prompted no model.
2. Its only outputs are *proceed* and *withhold*. It cannot size, side, sequence or price an order.
3. A withhold is a tagged, registered, durable event (§4), scored by G-COMPLETE as a missing tick. It is not a G-EXEC event: no order was intended, because no decision was made — the same logic as the validator-scope ruling, one step earlier.
4. The rule is identical for every book.

Existing members: the market-open check, the boundary ledger, the spacing guard.

**Ruling 1 — fail-closed guards are admission class.** They change which ticks exist, never what a decision becomes at the venue. They do not consume the corrected-executor count, subject to §3's conditions.

**Ruling 2 — closing (b) is admission class only in a conforming construction.** The requirement is a property, not an implementation:

> **P1 (at-most-once).** No book is prompted in a tick, **and none of its orders is submitted — stop orders included** — when the venue holds an order for that book that the committed record does not account for.
>
> **Primary test — by order id, per book.** Withhold the book if the venue holds any order whose id carries this book's segment and a `cycle_id` that is not accounted for. A `cycle_id` is accounted for when it appears in **this book's** committed decision log, or in a committed, ledgered repair record for this book. Another book's row for the same cycle does not account for it (the fourth route in §1). The query window opens at the book's last committed cycle and **never advances past an unaccounted order**: once found, an order stays in every later test until a ledgered repair accounts for it. A withhold event must not move the window.
>
> **Secondary test — by quantity.** The existing `reconcile`, at the registered post-cycle bounds, unchanged. It withholds exactly where the post-cycle check would halt and introduces no tolerance of its own. It exists for what an id cannot see: an order placed outside the pipeline, a corporate action.
>
> **Venue unreachable.** If the pre-trade query cannot be completed, P1 cannot be evaluated and the venue books are withheld (fail-closed, as Gate A).
>
> **Scope of a withhold — the scope the post-cycle handler would apply to the same state.** If the quantity test fails, **every venue book is withheld**: the handler halts every venue book on any divergence, so letting the other books trade buys one tick and ends in a persisted cohort-wide halt, with cross-book misattribution possible in between. If the quantity test is clean and only the id test fails — the book's state holds its fills and its decision row is missing — that book alone is withheld. Either way the id names the book to repair. **A withhold sets no halt flag**: it is re-evaluated every tick and clears when a ledgered repair accounts for the order.
>
> **P2 (durability).** The evidence P1 reads must be durable before, or atomically with, the first order it protects against. A file in the runner's working tree is not.

**Why the id is primary (hub amendment 1).** The reconcile carries a known cash gap of about $0.27, growing about 4¢ a night, and unposted dividends. A tolerance wide enough to ignore that noise can hide a small duplicate, and one tight enough to catch the duplicate withholds on the noise — the undifferentiated-failure principle in a new place. Set membership has no tolerance. Every decision row since 2026-11-02 carries a `cycle_id` in the order id's format, failed-call rows included (checked on all six November logs at `3d1c04a`), and the only other callers of `build_order_id` are the barrier probe's administrative books, which carry their own segments.

**What fail-closed costs here, stated.** A tick withheld because the venue is unreachable loses the decision as well as the orders. Without the withhold those ticks would have been decision-estimable (execution-impaired). Prompting and then blocking submission would keep the decision but is a change after the decision exists — executor-class by this ruling's own boundary — and the decision would rest on a book state nobody could verify. The loss is accepted and disclosed per §4.

**What a withhold suspends, stated (rev. 4).** The per-position stop is evaluated inside the book's tick, before the prompt (`_position_stop_sweep`, `pipeline.py:265`), and is submitted through the executor; it is not a resting order at the venue (*to confirm*, §6 item 7). A withheld book therefore evaluates no stops. That is correct for a book whose state is unaccounted — a stop computed on a stale position is the duplicate SELL of §1, cross-book misattribution included — and it has a price: **positions in a withheld book are unprotected by the stop until the book is admitted again**, and a cohort-wide withhold (a guard unreadable, the venue unreachable, a quantity divergence) suspends every venue book's stops for as long as it lasts. This is the existing meaning of a missed tick, with new causes that persist until a person repairs them. **Time-to-repair is therefore a risk parameter, not a convenience:** the repair runbook states a target and says what a person does about open positions if it is exceeded, and that target goes on the Go/No-Go sheet.

Constructions that satisfy both, in order of preference:

- **(V) Pre-trade venue check — recommended.** Before prompting, in broker modes, run the primary and secondary tests above. A failure withholds at the scope above and pages. This is the only construction whose evidence is written by the act that creates the risk; it covers all four routes in §1 and the next-slot path, and it needs no new marker. It is placed ahead of the fetch-start stamp, so the registered latency stages are unaffected.
- **(C) Claim before trading.** Commit and push a claim for the slot before the model loop; abort if the push is rejected. The code already names this (`pipeline.py:700`: "the atomic claim-commit hardening"). It gives at-most-once per slot for same-slot retries. It does **not** cover the next-slot path, so on its own it does not satisfy P1.
- **Per-book marking after the fill** does not satisfy P2 and is not a conforming construction. It may be kept as a convenience on top of (V).

Whether a later run may complete a slot for the books that did not fill is Operations' call; the record treats the others as missing legs either way.

**What would make either change executor-class:** any edit on the path from a parsed decision to a submitted order — sizing, the validator, order construction, the barrier, the fill wait. Reusing `reconcile` by call is not such an edit; changing it is a reconciliation-class change and is reviewed as one.

## 3. Must they land before 2026-12-01, and what does it cost

**Both are go-live gates.**

- **Gate A — guards fail closed.** A guard that trades when it cannot guard is not a guard. The fail-open rationale was to avoid a *silent* halt; a withhold that pages CRITICAL and writes a tagged event is not silent, and the cost asymmetry has reversed since it was written: in Phase A a missed tick cost completeness and a duplicate cost nothing; in Phase B a missed tick is one tolerated missing observation and a duplicate is an unrecoverable record defect.
- **Gate B — P1 and P2 hold.** The code's own comment is the gate: not live with real money without it.

**Cost under S1.** The registered state is 13 corrected-executor sessions (2026-11-11 through 11-30; `ghost_position_ruling.md`: "Landing 2026-11-11 leaves 13 corrected-executor sessions against the 15-day floor: **S1's conditional branch is invoked**"). The branch's own floor is in the boundary amendment: "below 10, November is not a validation month and S2 governs again." An executor-class change first effective on 11-17 leaves 9 sessions; on 11-18, 8. **So there is no executor-class budget left: an executor-class landing from today forward ends November as a validation month.** The hub's "zero margin" understates it — the margin is negative.

**The count is kept only if all four conditions hold. They are fixed now, before any of them is evaluated; failing any one makes the change executor-class with the consequence above.**

1. **Diff scope.** The landed diff changes no line on the path from a parsed decision to a submitted order. Operations' report lists every file touched; the hub checks the list against §2's last paragraph.
2. **Verdict replay.** For every tick since 2026-11-11, the new guard code, run against that tick's committed pre-state, returns *proceed* for every book. Zero differences on the validated record. **For (V)'s primary test the replay is one offline set difference and runs before shadow starts:** every order in the venue's history since the 2026-11-06 cutover whose id carries a book segment, against that book's committed decision log. The expected result is the empty set. Anything in it is either a structural class not yet registered or a lost run already in the record; both are findings, reported before the shadow lands, and this count is the base rate asked for in §6. **Result (Operations, 2026-11-16 20:06): the empty set** — see §6 item 3. For the secondary test, the pre-trade verdict at tick *t+1* must equal the post-cycle verdict recorded at tick *t* wherever nothing intervened; differences are listed and explained (dividends, fees, settlement).
3. **Shadow before enforce, for (V).** The pre-trade check lands logging-only first and runs in shadow on live-path sessions. It flips to enforcing only when all three hold: (a) **every expected verdict was emitted** — one per venue book per tick, each recording how many venue orders it examined; a shadow that did not run also reports zero withholds (CLAUDE.md rule 9); (b) zero unexplained shadow withholds; (c) the positive control has passed — demonstrations (iii) and (iv) below have shown the same code saying *withhold*. The flip is a configuration change recorded in the ledger. **Revert rule, fixed now:** a false withhold under enforcement before 2026-12-01 returns (V) to shadow by the same flag, ledgered; go-live then rests on the fail-stop, and (V) re-enforces only at a registered boundary.
4. **Induced demonstrations, added to S1's named list** (S1's branch already requires all named demonstrations passed). **None runs inside a production validation tick or on a validation book (hub amendment 3).** An induced withhold on the validation cohort is a missing validation tick; an induced uncommitted fill on a validation book is a `DECISION_RECORD_LOST` event in the record being validated. Demonstrations that need a venue run on a **separate paper account**. A test book inside the validation account is permitted only if the induced position is declared in a committed administrative record before the demonstration, so the validation books' reconciliation accounts for it; otherwise it lands on the orphan line as an organic-looking G-BOOK event, and S1's branch requires zero of those unresolved. The demonstrations:
   - (i) ledger present and unreadable → no model prompted, CRITICAL, tagged event;
   - (ii) decision log unreadable → same;
   - (iii) a run stopped after its first fill, then a same-slot re-run and the next slot's run → in both, the id test names the filled book, the quantity test fails, and every venue book is withheld; no halt flag is set;
   - (iv) a completed run whose push is made to fail → the next run withholds every venue book, the id test naming each book that traded;
   - (v) **month rollover, guards** — the first tick of a month, when `data/trades/{book}_{month}.jsonl` does not yet exist: absent is normal and must proceed;
   - (vi) **venue unreachable at the pre-trade check** → venue books withheld, CRITICAL, tagged (hub amendment 1);
   - (vii) **month rollover, (V)** — the last cycle of one month and the first tick of the next: the primary test must find the prior month's cycle ids and proceed. The shadow window does not cross a month boundary, and the first enforcing crossing is the first live tick;
   - (viii) **a book that raises after its orders inside a run that commits** (the fourth route) → two branches, both demonstrated: raised **before the save** — the same run's post-cycle reconciliation halts every venue book, and the next tick's quantity test withholds them all; raised **after the save** — reconciliation is clean and at the next tick the id test withholds that book alone;
   - (ix) **the fail-stop** — a failed run and a cancelled run, each having submitted an order → the workflow is disabled; a failed run that submitted none → it is not; a run whose orders cannot be determined → it is.

Demonstrations (v) and (vii) are the traps. Both guards already distinguish *absent* (normal: first tick of a day or month) from *present and unreadable*. Fail-closed applies only to the second. A fail-closed change that blocks on absence blocks the first live tick.

**Precise blocking conditions (registered):** the ledger blocks when the file is present and cannot be parsed. The spacing guard blocks when any enabled book's present log raises on read, or when no present log yields a parseable final row; one torn final row with other books readable remains an answer, as today.

**The fail-stop (restated per hub amendment 2 — a build, not an existing behaviour).** The first issue of this ruling described the fallback as the existing failure-notification job disabling the workflow. That job only notifies; nothing disables anything today, and its condition excludes cancelled runs. The registered requirement:

> On failure **or cancellation** of an intraday run in a broker mode, if the run submitted any order, the intraday workflow is disabled and stays disabled until a person has reconciled the books to the venue and the re-enable is ledgered. Whether the run submitted an order is determined from the venue, by order ids in the run's window — the dead runner cannot be asked. **If that cannot be determined, the workflow is disabled.**

It is workflow-level and outside the order path. The hub is building it this week as a second layer regardless of (V). Its limits, stated: it keys on run failure, so it does not see the fourth route in §1, where the run succeeds; there the same run's post-cycle reconciliation covers **only the pre-save half** (§1), and it does so by halting the whole cohort. The post-save half — orders and book consistent, decision row lost — is invisible to the fail-stop and to reconciliation alike.

**Gate B is met by (V) enforcing.** If (V) is not enforcing on 2026-11-30, go-live requires the fail-stop armed and demonstrated, the Go/No-Go record says the lab is live on the second layer alone, **and condition 2's offline set difference runs after every session's close** — it is then the only instrument that can see the fourth route's post-save half, as a `DECISION_RECORD_LOST` finding the next morning rather than a withhold at the next tick. With neither layer, No-Go.

## 4. Record classes (registered; closed sets extend only by registration)

| Class | When | Scored by | Note |
|---|---|---|---|
| `TICK_WITHHELD_GUARD_UNREADABLE` | A guard's file is present and unreadable | G-COMPLETE, all books | One event, correlated across the cohort by construction; disclosed as such |
| `TICK_WITHHELD_VENUE_UNREACHABLE` | The pre-trade venue query cannot be completed | G-COMPLETE, all venue books | Correlated by construction. Also counted in the venue-availability descriptor, so the shift of these ticks out of G-EXEC is visible |
| `BOOK_WITHHELD_UNACCOUNTED_ORDERS` | The id test fails for the book and the quantity test is clean | G-COMPLETE for the book; G-BOOK event | The book stays withheld until repaired; repair is administrative, attributed by order id, ledgered, and is what accounts for the `cycle_id` |
| `TICK_WITHHELD_BOOKS_DIVERGED` | The quantity test fails pre-trade, with or without an id failure | G-COMPLETE, all venue books; G-BOOK event | The pre-trade form of the post-cycle halt, without the persisted flag. Symmetric across arms by construction; where the id test also failed, the event names the book to repair |
| `DECISION_RECORD_LOST` | A venue fill exists with no committed decision row | Data-integrity ledger | The book-tick is a missing leg for RQ1 and RQ3; RQ2 and RQ5 take the entry from the venue fill and flag it. Expected count zero; any occurrence is an incident |

**Rename, flagged:** the first issue called the third class `BOOK_WITHHELD_UNCOMMITTED_FILLS`. Under amendment 1 the trigger is an unaccounted order, filled or not, and under the fourth route the run did commit; a class name that misstates its trigger is the "Insufficient cash" mislabel again. No code carries the old name yet.

`DECISION_RECORD_LOST` names a limitation these fixes do not remove: a decision row is written after its orders (`pipeline.py:477`, then `:535`) and is durable only at the end-of-run commit, so an order can outlive its decision. Making the row durable before submission is a larger change and is not required for 2026-12-01; it is registered as a known limitation and a Phase B review item. Classification follows what happened: the fills are real and stay in the book; nothing is reconstructed.
