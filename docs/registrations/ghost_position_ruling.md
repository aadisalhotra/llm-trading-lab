# Ghost-Position Threshold Ruling — Fix A, Reconciliation Tolerance, Orphan Line, Disclosure

- **Artifact:** `docs/registrations/ghost_position_ruling.md` — governing text. Lands with fix A and the reconciliation-parameter change under one sign-off.
- **Ruled:** 2026-11-09 (Research), by close, on Operations' corruption-path trace. **Quoted code and config verified against origin `ad77c7d`.**
- **The defect:** `src/portfolio/portfolio.py:311` sets `GHOST_SHARES_EPSILON = 0.01`; `sell()` deletes a holding when `h.shares < self.GHOST_SHARES_EPSILON` (`:326–327`) after crediting proceeds only for the shares sold — the remainder vanishes from the ledger uncredited while the broker keeps the shares; `src/execution/executor.py:879` calls `sweep_ghost_positions()` after every SELL, deleting *any* book holding under 0.01 share. Level-2 reconciliation is defined by `config/settings.json` to the same constant — *"Position tolerance is Portfolio.GHOST_SHARES_EPSILON by construction, so level 1 and level 2 agree on what 'no position' means"* — so the tolerance that should detect the deletion is its own threshold. At $2,000 books, 0.01 share of LLY is $13.93 (0.7% of NAV); cash-capped BUYs on high-priced names now routinely create sub-0.01-share holdings (e.g., $9.60 of settled cash → ~0.007 LLY). Realized so far: one event — an NVDA remainder of 0.0001 share ($0.0174) left by float truncation on a full exit. **Fifth appearance of the scale relic:** a share-unit threshold harmless at $100k and wrong at $2,000; sibling of the one-share executor floor.

## ① Fix A is book-record-class, not executor-class; it does not consume the stricter S1 count

**Fix A:** keep remainders; delete a holding only at ≤ 1e-9 shares — the venue's quantity precision (`truncate_qty`, `broker.py:142`: "Truncate to the venue's 9-dp quantity precision"), so the ledger's "no position" equals the venue's. It changes no order and no quantity; it changes the book record so it matches the broker.

**Class boundary, registered:** *executor-class* = any change that alters the venue order a given decision-and-state would produce (sizing, skip paths, submission, deadline semantics) — such changes invalidate prior sessions as evidence about that path and consume the stricter validation count. *Book-record/reconciliation-class* = any change to how fills are recorded or compared, where the broker is authoritative and the record moves toward it — prior sessions' venue-path evidence stands. Fix A is the second class. **The corrected-executor count remains 15; fix A does not reduce it.**

**Why not visibility-only:** tightening tolerance without A converts silent deletions into organic G-BOOK events; the conditional branch requires zero of those. A prevents the divergence; the tolerance (§②) detects any residual. They land together.

## ② Level-2 position tolerance — $1-equivalent per name; 0.1% of book capital aggregate

- **Per name:** tolerance = $1.00 expressed in shares at the current mark (≈ 0.0007 share of LLY; 0.05 share of a $20 name). Basis: $1 is the venue's notional floor and the registered `cash_tolerance_usd` — a sub-$1 divergence on one name is *unactionable* (no corrective order can be sent below the venue minimum), so it is the natural dead-band; any divergence ≥ $1 is actionable and must reconcile.
- **Per book, aggregate:** alert when Σ|per-name divergence| exceeds **0.1% of `BOOK_CAPITAL_PHASE_B`** ($2.00 at the current value), so many sub-$1 divergences cannot hide a real problem; tied to the registered parameter, not a constant.
- **"No position"** at both levels = < 1e-9 shares (venue precision). The settings note's "by construction" sentence is rewritten in the same landing to state this (rule 10 — the restatement must agree).
- Both values enter `reconciliation_params` as registered parameters; the share-denominated constant is removed from the reconciliation definition.

## ③ Orphan line — a reconciliation participant

Broker positions owned by no book are registered as an **orphan ledger line**, a participant in the aggregate reconciliation alongside the reserve: Σ(book holdings) + orphan = broker positions, per name, each cycle. **Expected exactly empty.** Any orphan ≥ $1 notional is a **G-BOOK alert** (a book lost an actionable holding). Any orphan < $1 is a `WARNING`; where the originating book is identifiable from the fill record, the holding is **re-attributed to that book** with a ledger entry — a correction of the record toward the broker-authoritative truth, i.e., a record correction of a defect's effect, not a reclassification of behaviour. Unattributable sub-$1 orphans are carried on the orphan line and disclosed.

## ④ Disclosure

1. **NVDA remainder:** one event — 0.0001 share, $0.0174, float truncation on a full exit; deleted from the ledger by the 0.01-share sweep while the broker held it; re-attributed to the originating book under §③; inside the new tolerance; disclosed as the single realized instance of the corruption path.
2. **RTX remainder:** 1e-9 share, from float representation in `truncate_qty`; held under fix A's threshold and disclosed; at the venue-precision edge by construction.
3. **The class:** `GHOST_SHARES_EPSILON = 0.01` was a Phase A design constant ("dust positions left behind by fractional rounding — they clutter the dashboard and confuse the model," per its docstring) harmless at $100k and, at $2,000, a concealed hole of up to 0.7% of NAV per name. No divergence above the new tolerance has occurred.
4. **Structural rule (registered; the census of share-denominated constants lands against it):** *no fixed share-denominated threshold anywhere in the pipeline. Every threshold derives from venue quantity precision (`QTY_DECIMALS`) or from a dollar bound tied to a registered quantity (venue minimum; `cash_tolerance_usd`; `BOOK_CAPITAL_PHASE_B`).* A constant that fails this test is a scale relic by definition and is corrected before Phase B, in the class §① assigns it.

## ⑤ Metrics position floor — a dollar bound, not a share constant (ruled 2026-11-09, same day)

`src/analytics/research_metrics.py:84` sets `SHARES_EPSILON = 0.01` ("mirrors Portfolio.GHOST_SHARES_EPSILON"), consumed at `:508`, `:747`, `:756`, `:816` in the fill-replay that reconstructs positions for RQ2/RQ3. The registered closure rule (`:713–715`): *"A position counts as closed ONLY when the segment's closing side takes residual magnitude below SHARES_EPSILON. Partial trims never close a position (pre-registered)."* Under the share constant a $9.60 holding of 0.007 LLY is treated as no position, and at `:747` a further fill on it resets the entry date — the measurement was already wrong at $2,000 before fix A.

**Registered definition:** a *behavioural position* is a reconstructed holding with notional ≥ **$1.00** (`BEHAVIOURAL_NOTIONAL_FLOOR` = the venue minimum = `cash_tolerance_usd`) at the **fill price of the fill being processed** — deterministic from the fill record, no mark dependence. `SHARES_EPSILON` is replaced by `dust_threshold_shares(fill_price) = BEHAVIOURAL_NOTIONAL_FLOOR / fill_price`. *Closure:* a position closes when the closing fill takes residual notional below $1; the realized leg is computed over the closed portion; the sub-$1 residual is disclosed as dust, not classified (it is unactionable — no order can realize it alone — so it carries no realization-timing information). *Entry:* a fill opens a position when the prior residual notional is below $1. *Weight-based metrics* (RQ5 gross-weight HHI) take no floor; dust self-weights to ~0. The book keeps every share truthfully; the metrics measure behaviour. The count of dust residuals is a disclosed descriptor.

**⑤(b) — `scripts/defab_clean_window.py` (ruled 2026-11-10; verified at origin `0f9eec1`).** Two fixed share thresholds: `:61` `GHOST_SHARES = 0.01  # mirror Portfolio.GHOST_SHARES_EPSILON` — now a dangling mirror of a removed constant — and `:70` `OVERSELL_SHARES_MIN = 0.05`, whose comment states that *"The audit's own conservation test uses a $1 cash / 0.05 share tolerance; we match it."* Ruling: both convert to the registered dollar derivation — `:61` to `BEHAVIOURAL_NOTIONAL_FLOOR / fill_price` (the §⑤ definition), `:70` to the §② per-name tolerance ($1-equivalent at the fill price) — and the April–May clean-window de-fabrication audit **re-runs as an output-version event**; its published counts (the conservation record's zero genuine violations and the 0.0001-share sweep-dust classification) are compared before and after, dual-published if any count moves. At $100k books the economic effect is expected to be nil (0.05 share ≈ $70 ≈ 0.07% of NAV), but expected is not computed. **The third site:** the comment at `:69–70` says the conservation audit itself tolerates 0.05 share per name. If that tolerance runs against live $2,000 books it is a 3.5%-of-NAV hole on LLY — a share relic inside the integrity audit. The census must locate it and convert it to the §② rule before the first live-book conservation certification. **Census guidance:** every `# mirror X` comment is a dependency edge — three sites mirrored one constant; the census treats each such comment as a site to sweep, not documentation.

**Classification:** an amendment to a pre-registered closure rule — an **output-version event**. Phase A recomputes under the new floor; for prices above $100 the $1 bound is tighter in shares than 0.01, so residuals between $1 and ~$14 on high-priced names may reclassify. Computed, not asserted: any published RQ2/RQ3 figure that moves rides the output-version ledger with dual publication. The `MAX_POSITIONS` validator count is a book-side rule and is unchanged by this measurement ruling.

## ⑦ Dust positions in model-facing state — ruling (2026-11-10)

**Finding:** since fix A, Grok's prompt shows its 0.0001-share NVDA remainder ($0.02); Grok issued SELL on it in 6 of 13 cycles on 2026-11-10. The order can never execute (venue minimum $1). Roughly 10% of full exits leave such a remainder: the executor truncates exit quantities to 4 dp (`executor.py:667`) against the venue's 9-dp precision, so the remainder is created by our precision constant — the one-share floor's sibling, and the sixth scale relic.

**Ruled: (c) — full-quantity exits at venue precision, so no dust forms.** A full exit sells the exact holding truncated to 9 dp (`truncate_qty`), leaving ≤ 1e-9 share, which fix A's threshold deletes. This removes the cause. (a) was rejected because the defect compounds — each remainder permanently occupies a position slot and generates futile SELL decisions every cycle, and over a year of exits a book can exhaust its 50 slots on dust, at which point `MAX_POSITIONS` drops real buys: behavioural distortion induced by our constant. (b) was rejected because an administrative liquidation faces the same venue minimum and treats the symptom on every recurrence.

**Count consequence, stated:** (c) alters the venue order a decision-and-state produces — **executor-class** under §①'s boundary. Landing 2026-11-11 leaves 13 corrected-executor sessions against the 15-day floor: **S1's conditional branch is invoked** — all named demonstrations passed, zero unresolved organic G-BOOK/G-EXEC events, explicit hub sign-off. Accepted: a late-found order-path defect is better validated for 13 sessions than frozen unfixed for the confirmatory year. Any other executor-class census item lands in the same push so the count restarts once.

**Existing dust (the NVDA remainder and any other pre-(c) dust):** Operations verifies whether the venue's full-position close endpoint accepts a sub-$1 position. If yes: a one-off administrative liquidation of existing dust, tagged boundary-administration, censored and disclosed (the force-cover class). If no: existing dust remains in the book truthfully, excluded from the behavioural position set (§⑤), and resolves naturally if the model re-buys the name above $1.

**Metrics treatment of dust-sell decisions (registered with §⑤):**
- A dust-sell intent is blocked pre-submission as `BELOW_VENUE_MINIMUM` — a registered, tagged constraint event — and, per the censoring principle, enters no behavioural metric.
- **RQ2:** no realization occurs and dust is not a behavioural position; dust-sell intents enter no disposition classification.
- **Turnover and activity metrics:** computed on executed trades; dust-sells never execute and do not enter.
- **RQ1:** actions on dust holdings are **outside the registered decision set**, as SHORT/COVER are — the (model, ticker, tick) cell is excluded from the concordance computation and from that model's ruled-on ticker set for the within-tick null (not recoded to HOLD, which would be a counterfactual). An amendment to RQ1's decision-set scope, registered before any confirmatory tick.
- **Disclosed descriptor:** dust-sell attempts per model per session — behaviour in response to true state, reported, not an estimand. The repeated attempts are interesting (a tidiness response to an unactionable holding) and belong in the descriptive record, where they can be read without contaminating the estimands.
