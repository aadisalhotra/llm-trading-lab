November 18, 2026

Feature

Gemini 4 Neon (GA)

Gemini 4 Neon (gemini-4-neon) is generally available (GA) in Gemini Enterprise Agent Platform. Gemini 4 Neon is a Google Frontier Model subject to Section 34 of the Service Specific Terms (for details, see Abuse monitoring) and delivers high-performance coding, multi-step reasoning, and multimodal understanding at low latency for agentic enterprise workflows:

  • Unified 1,048,576-token limit and long decodes: Supports a unified 1,048,576-token input and output limit, where output includes thinking, function calls, and the final response. Single foreground segments generate up to 65,536 output tokens for streaming and non-streaming requests. Long decodes (continuation_token) extend output up to 1,048,576 tokens (minus input tokens) on the Interactions API and GenerateContent (v1beta1). The Interactions API also supports asynchronous server-managed background execution (background=true).

  • Thinking levels (LOW, MEDIUM, HIGH, and XHIGH): Supports four thinking levels, with HIGH as the default and XHIGH for deep reasoning workloads. Setting thinking_budget or thinking_level="MINIMAL" returns an HTTP 400 validation error.

  • Implicit context caching with durable caching: Supports automatic implicit context caching with durable caching enabled by default for shared prompt prefixes of 4,096 tokens or more (explicit context caching isn't supported).

  • Cache write control and pricing: Starting on January 12, 2027, Gemini 4 Hydrogen and later models support cache control features with TTL configuration. You choose what to cache and how long cached content stays valid through TTL configuration. Cache writes are billed at 1.25x the standard input token price by default, and longer retention costs more. For details, see Gemini 4 pricing.

  • Office and OpenDocument file inputs: Supports Microsoft Office (.docx, .dotx, .doc, .pptx, .ppt, .xlsx, .xls) and OpenDocument (.odt, .odp, .ods) files inline or from Cloud Storage (gs://), including inside multimodal FunctionResponse parts.

  • Capabilities, consumption options, and endpoints: Available on the global endpoint and in the us and eu multi-regions across GenerateContent, the Interactions API, and the OpenAI compatibility Chat Completions API. Supports function calling, code execution, computer use, URL context, and Agentic video understanding. Grounding options include Grounding with Google Search, Google Maps, Web Grounding for Enterprise, and Parallel and Exa Web Search. Consumption options include Standard PayGo with Usage Tiers, Priority PayGo, Off-peak PayGo, batch inference, and Provisioned Throughput.

For model specifications, code examples, and migration guidance from Gemini 3 models, see Gemini 4 Neon, the developer's guide to Gemini 4 Neon, and Get started with Gemini 4.

Feature

Deferred tier for asynchronous model calls on the Interactions API

The Deferred tier (service_tier="deferred") is available in General Availability (GA) on Gemini Enterprise Agent Platform. You can run asynchronous Gemini model calls on the global Interactions API endpoint for custom and third-party agents.

The Deferred tier includes the following capabilities:

  • Discounted token pricing: Deferred model calls are billed at a 50% discount compared to Standard PayGo rates, and deferred requests don't fall back to Standard PayGo. For billing details, see Pricing and billing.
  • 24-hour target and 7-day state retention: Enqueue requests (background=true, store=true) that target a 24-hour completion window. Interactions retain server-side state for 7 days to support previous_interaction_id chaining. Deferred model calls use the Flex PayGo per-base-model request quota.
  • Google Gen AI SDK and REST support: Create, poll, stream, and cancel deferred calls using REST or the Google Gen AI SDK for Python and Node.js. To schedule Agent Development Kit (ADK) agents on the Deferred tier, see Autonomous agent scheduling.
  • Supported Gemini 4 and Gemini 3 models: Supports gemini-4-carbon, gemini-4-argon, gemini-3.8-flash, gemini-3.7-flash, gemini-3.6-flash, gemini-3.5-flash, gemini-3.5-flash-lite, gemini-3.1-flash-lite, and gemini-3.1-pro-preview on the global endpoint. Projects with allowlist access can also run gemini-4-carbon-cyber-permissive and gemini-4-argon-cyber-permissive.

For more information, see Use the Deferred tier and Interactions API overview.

Fixed

CodeMender updates (v0.22.0)

This release introduces updates to CodeMender:

  • Execution time limits: Added the --duration flag (alias --timeout) to cm find, cm fix, cm verify, and cm session resume. You can also set the limit with the CM_DURATION environment variable. When the limit is reached, CodeMender stops the run, reports the results found so far, and exits with code 50. On cm find --diff, the --fail-on gate is evaluated first, so a blocking finding still exits with code 1.
  • CSV export and import: cm find and cm report now support --format csv and .csv output files, and cm report import accepts CSV files.
  • Exit codes: cm now exits with code 2 for general failures and for sessions that the prompt injection filter stops. Exit code 1 is reserved for CI gate failures.
  • Bug fixes:
    • Fixed an issue in file discovery where comments or strings that matched test patterns or generated-code markers caused source files to be skipped by cm find.
    • cm report import no longer creates duplicate findings when you import the same report more than once.
    • cm no longer sends Application Default Credentials (ADC) tokens to endpoints outside googleapis.com.
    • cm now warns when commands run outside the OS sandbox, for example with --sandbox=false.
    • The sandbox blocks hash-based Python bytecode (.pyc) files and removes bytecode created during a session.
    • cm removes bidirectional text controls and invisible characters from untrusted text before it displays the text.

For more information, see the CodeMender documentation.

Govern agents on any CNCF-conformant Kubernetes cluster with Agent Gateway for cross-cloud (Limited Preview)

Agent Gateway for cross-cloud is available in Limited Preview. It extends Agent Platform governance to agents that run on Cloud Native Computing Foundation (CNCF)-conformant Kubernetes clusters outside of Google Cloud, such as Amazon Elastic Kubernetes Service (Amazon EKS), Azure Kubernetes Service (AKS), Red Hat OpenShift, and bare-metal clusters. Your agents keep running where they are, but you govern them from one place: give each agent a verifiable identity, register agents and MCP servers in Agent Registry, and route their LLM, MCP, and A2A traffic through local Agent Gateway proxies by using your existing service mesh or network stack. Those proxies enforce access and Model Armor safety policies, and send access logs and agent traces to Cloud Logging and Cloud Trace.

Agent Gateway for cross-cloud is available at no charge during Limited Preview. Other products that you configure with it, such as Model Armor, Cloud Logging, and Cloud Trace, are billed at their standard rates. To request access, complete the access request form.

For more information, see Set up Agent Gateway for cross-cloud.

Feature

Inference request metadata logging (GA)

Inference request metadata logging is generally available. Gemini Enterprise Agent Platform can write one Cloud Logging entry for every inference request your project serves. Each entry records the model, region, consumption option, token counts, Provisioned Throughput usage, latency and error code. Entries record metadata only and never contain prompts or responses. Logging is supported for Gemini models that use generateContent and streamGenerateContent, and for Claude models that use rawPredict and streamRawPredict.

You can turn on logging in the Google Cloud console, from the Provisioned Throughput page, or with the REST API. Turning on logging in the console also turns on detailed metrics, which chart Provisioned Throughput traffic at one-second resolution. With logging on, the model observability dashboard adds 1-second resolution options to its charts for pay-as-you-go traffic. To attribute usage to a team, application or tenant, add request headers with the x-goog-agent-platform-observability-label- prefix, and query the entries with SQL in Observability Analytics.

For more information, see Log inference request metadata.

Security

Security update for Cloud Storage staging bucket verification

A security issue in the Python SDK (google-cloud-aiplatform) for Gemini Enterprise Agent Platform allowed potential Cloud Storage bucket squatting when staging local model artifacts without specifying an explicit staging bucket.

This issue has been resolved by adding bucket ownership verification and randomized naming for default staging buckets in Cloud Storage. Users of the google-cloud-aiplatform SDK should upgrade to version 1.165.1 or later, or ensure that an explicit staging_bucket belonging to their project is specified when calling Model.upload().
